# Multi-pass Review

多视角 Review 的目标是提高问题发现覆盖面，不把多个同源判断包装成多个真实 Reviewer。

## 1. 冻结共同 Review Packet

开始前固定所有 pass 共用的：

- manuscript / review-source version；
- Figures / Tables / Supplement；
- 当前允许读取的 data / code；
- target venue / evaluation criteria（若已知）；
- Assessment Boundary；
- 每个 pass 都应共同掌握的事实材料。

共同 packet 不包含前一个 pass 的 Concern、预期答案、主 Agent 的问题清单或其他 reviewer report。

## 2. 预先定义 review lens

需要不同 emphasis 时在开始前定义，例如 Design / internal validity、statistics / computational rigor、domain mechanism、external validity、literature / novelty、reproducibility / reporting。

这些是 review lens，不是虚构 Reviewer 的身份、机构或资历。每个 lens 仍须报告自己看见的会推翻 central Claim 的明显 validity failure。

## 3. 只有真实隔离才称 independent

只有当前执行环境提供真正相互隔离的 context，并且每个 context：

- 只收到同一冻结 Review Packet 和自己的 lens；
- 看不到其他 pass 的报告 / Concern；
- 独立重建 Claim 与 evidence；
- 在 synthesis 前冻结自己的报告；

才能称为 **independent / isolated review passes** 或互盲多视角评议。

同一 context 中顺序运行多个视角只能称 **multi-lens review**。不要因为分了几个标题就声称存在独立 Reviewer。

## 4. 先冻结，再综合

所有计划中的个体报告完成并冻结后才做 synthesis。综合可以：

- 合并实际指向同一底层问题的 Concern；
- 标出多个 pass 独立发现的相同问题；
- 保留单一视角发现但科学后果严重的问题；
- 对冲突判断回到 manuscript、prior work 与方法学 evidence，而不是投票。

不能在看到 consensus 后反向修改个体报告，也不能为了制造“多样性”删除真实重复问题。

## 5. Consensus 不是科学真值

多个 isolated pass 得出相同判断，只提高该问题的可发现性 / 审查显著性，不自动证明判断正确。一个只有单一 pass 发现的 central validity failure，也不能因为缺少 consensus 而被平均掉。

因此不通过 reviewer vote、平均分或加权总分决定 scientific validity、Claim 是否成立、是否需要新实验或稿件的最终编辑决定。

## 6. 汇报透明度

多视角结果应明确：

- 使用了多少 pass / lens；
- 是否具有真实 context isolation；
- 共用的 Review Packet 与 Assessment Boundary；
- 哪些问题是 post-hoc synthesis 后识别为同一 Concern；
- 哪些关键判断仍 unresolved / Not Assessable。
